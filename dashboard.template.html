What this is

A local, read-only view of your own Claude Code usage. It reads the transcript files Claude Code already writes under ~/.claude/projects, aggregates them, and serves the result on 127.0.0.1. Nothing is uploaded and nothing is sent anywhere — the one outbound request is the quota lookup described below, which goes to Anthropic over HTTPS. There is no login, no database, no telemetry.

Requirements: Python 3.11+. No third-party packages.

Running it

python serve.pyBuilds, serves on http://127.0.0.1:8787/, opens your browser. Leave it running; it regenerates on the configured interval and the open tab reloads itself. Ctrl+C stops it.
python build.pyOne-shot regenerate of output/dashboard.html, without serving. That file is entirely self-contained — you can open it directly or copy it elsewhere.
python emit_cube.pyJust the data step. Run standalone it writes cube.json next to the script, not into output/.

Start automatically at logon (Windows)

pwsh -File install.ps1Registers it to start hidden at every logon and starts it now. Runs pythonw serve.py --no-browser — no console window, no browser popup.
pwsh -File uninstall.ps1Stops the server and removes the auto-start. Leaves your files, config and generated output alone.

It tries a Scheduled Task first, which also restarts the server within a minute if it ever crashes. Registering a task needs elevation, so from a non-elevated shell it prints Access is denied and falls back automatically to a per-user logon Run key — still auto-starts, just without the crash-restart. For that too, run install.ps1 from an elevated PowerShell.

Once it's installed, bookmark http://127.0.0.1:8787/. Don't also run python serve.py by hand while it's up — they'd fight over the port.

The quota panel

The Overview section shows your live 5-hour and weekly windows — the same figures /usage reports. These are fetched from Anthropic's read-only OAuth usage endpoint using the access token already stored in your .credentials.json. The token authorises that one request; it is never logged or written anywhere. This lookup does not consume model quota.

Refresh cadence is deliberately gentle, because the endpoint rate-limits bursts: roughly every 30 minutes normally, 60 for an account sitting at exactly 0%, and 4 after a transient failure. The panel itself re-reads the cache every minute, so "updated Nm ago" is the age of the data, not of the page.

Unlike every other panel, quota is not affected by the filters — it is a live reading, not history.

Statuses you may see

not signed inThat account's token was rejected. Run claude for it once to sign back in. The dashboard deliberately never refreshes tokens itself — doing so rewrites .credentials.json, which a live session for that account owns.
panel missingNo .credentials.json was found for any configured account, so there is nothing to show.

The verdict line

Beneath the bars, one sentence states the conclusion rather than leaving you to derive it. If a 5-hour window is exhausted it names the account with headroom and counts down the wait. Otherwise it judges the week against elapsed pace, which is the only way a weekly percentage means anything: 82% spent is fine on day six and alarming on day two.

Using more than one account

Most people have one, and a stock install needs no setup — ~/.claude is found automatically. If you do run a second login, Claude Code has to be told to use it, and there are two ways to do that. Which one you pick changes what this dashboard can show you, so pick deliberately.

Option A — one config, separate credentials recommended

Both accounts share ~/.claude — same settings, same MCP servers, same memory, same project history — and only the stored credential differs. Point CLAUDE_SECURESTORAGE_CONFIG_DIR at a second folder and define a shortcut for it.

Git Bash / zsh — add to ~/.bashrc or ~/.zshrc:

alias claudeb='CLAUDE_SECURESTORAGE_CONFIG_DIR="$HOME/.creds-b" command claude'

PowerShell — add to your $PROFILE:

function claudeb { $env:CLAUDE_SECURESTORAGE_CONFIG_DIR = "$HOME\.creds-b"; claude @args }

Open a new shell and run claudeb once. It has no credential yet, so it will take you through the normal browser login — sign in as the second account. From then on claude is account A and claudeb is account B. command claude in the alias is what stops it recursing into itself.

Then list both in config.toml — dir is the folder holding that account's .credentials.json, and label is what appears beside its bars:

accounts = [
  { label = "A", dir = "~/.claude" },
  { label = "B", dir = "~/.creds-b" },
]

What you get: both quotas, side by side. Usage covers both accounts, because both write to the same transcript folder — but for that same reason it arrives combined. Nothing on a record says which account produced it, so tokens, calls, projects, models and sessions are the total across both, and no amount of work on this tool can split them.

One caveat: CLAUDE_SECURESTORAGE_CONFIG_DIR is undocumented. Confirm your Claude Code version honours it — run claudeb and check it prompts for a fresh login rather than reusing account A — before relying on it.

Option B — a config directory per account splits usage

Each account gets its own settings, MCP servers, memory and its own transcripts. Override CLAUDE_CONFIG_DIR instead:

alias claudew='CLAUDE_CONFIG_DIR="$HOME/.claude-work" command claude'
function claudew { $env:CLAUDE_CONFIG_DIR = "$HOME\.claude-work"; claude @args }

Run claudew once and sign in as the second account, exactly as above. Because the whole config directory moves, that account's credentials and its transcripts live inside it — so one entry per account covers both quota and usage:

accounts = [
  { label = "personal", dir = "~/.claude" },
  { label = "work",     dir = "~/.claude-work" },
]

Transcripts are looked for at <dir>/projects for each account. If yours live somewhere else, say so explicitly with a transcripts key:

{ label = "work", dir = "~/.claude-work", transcripts = "D:/claude-work/projects" }

What you get: everything Option A gives you, plus real per-account usage. The dashboard reads every account's transcripts directory, and because the folder a transcript came from is the account, attribution is measured rather than inferred. A By account panel appears in Usage, and clicking an account isolates it across every other panel — daily volume, projects, models, effort, hours, heatmap, limit episodes and sessions all follow. Sessions carry the owning account too.

Two things stay combined even here: the Tooling attribution panels (tools, MCP, skills), which are noted as such in that section, and anything Claude Code writes outside a configured directory.

Which to choose

Option A — shared configOption B — separate configs
Quota per accountYesYes
Usage completeYesYes
Usage split per accountNo — impossible, not merely unimplementedYes — measured
Shared settings, MCP servers, memory, historyYesNo — each account is its own world
Relies on an undocumented env varYesNo

So: pick A if you want one environment and only care about watching two quota pools. Pick B if you want to know which account the work actually went to, and don't mind maintaining two configurations.

Reading the page

  • Sections in the rail split the console into Overview, Usage, Patterns, Tooling and Limits. Your last section is remembered.
  • Filters live in the rail permanently, so nothing ever floats over your data. Granularity (day / week / month) and the date range apply to every section. The presets fill the From and To boxes, which are what actually filter — type into either, or click one to open a calendar, for any range you like. The preset highlight drops away as soon as the dates stop matching it, and a range entered backwards is swapped rather than showing you nothing.
  • Click to isolate. Clicking a project, model, effort level or legend chip filters every other panel to it. Click again, or Reset filters, to clear.
  • Focus under Tooling → Token cost by: the Sessions and Workspaces tables carry a focus button per row. Focus as many as you like to compare them; click focused again to drop one. Workspaces share their filter with the Where the tokens go bars, so the two always agree.
  • Every active filter appears as a chip in the rail, and each chip's × clears only itself. Reset filters clears the lot.
  • Hover anything in Tooling — a row, a column header, a tab — for what it is, its full id (MCP tools are shown shortened) and its numbers spelled out.
  • Cache economics in Usage splits the tokens in view into cache reads, cache writes, output and fresh input, and charts reuse over time. Sessions, workspaces and every Tooling row carry a Reuse figure of their own — how many times each cached token was read back. A low one means context was being rebuilt rather than re-read.
  • Cross-filtering computes each facet with every filter except its own, so you can always see what else exists to switch to.
  • Collapse any panel by clicking its heading, or use Collapse all. Collapsed state is remembered.
  • Log scale appears automatically on a bar list spanning 2+ orders of magnitude, labelled underneath. Without it the long tail is an invisible sliver — your model volumes run from billions down to hundreds of thousands.
  • Percentages. VIEW is the share of everything in the current date range. In Tooling a second column (TOOLS, SKILLS…) is the share within that category — those categories cover a slice of your tokens, not a partition, so both numbers are needed. Lists that do partition (projects, models, effort) show only VIEW.
  • Theme follows your OS until you use the toggle, after which your choice sticks across reloads.
  • Filters, section, collapsed panels and theme all persist, so the periodic auto-reload never disturbs your view.

Resuming a session

Under Tooling → Token cost by → Sessions is every session, sortable by any column, with focus and copy buttons. Resume one with:

claude --resume <id>

Sessions are placed by when they were last used — the timestamp shown, and the one that matters for picking one back up.

Troubleshooting

SymptomCause and fix
Page won't load / port in useThe logon task is probably already serving it. Open http://127.0.0.1:8787/ rather than starting a second copy, or change port and restart.
Quota panel absentNo .credentials.json found. Sign in with claude, or point accounts[].dir at the right folder.
Quota stuck at an old readingExpected after a failed fetch — the last good numbers are kept and only the age grows. It retries on its own.
"Today" shows nothingYou haven't run Claude Code yet today. Today is the wall-clock day, not the most recent day with data.
Days or hours look shiftedtz_offset_hours doesn't match your actual timezone.
A project is missingWhere the tokens go shows the top ten only. Tooling → Token cost by → Workspaces lists every one, sortable.
Every panel is emptyThe date range selects no data, or a focused session sits outside it. Check the filter chips in the rail — each × clears one — or press Reset filters.
Filters were forgotten onceExpected on the first load after upgrading to the from/to date range: the saved format changed and the old value had no equivalent. They persist again from then on.
A second account's usage is missingIts transcripts directory isn't being read. Add the account to accounts so <dir>/projects is picked up, or point a transcripts key at the right folder. Note an explicit transcripts_dir overrides all of that.
No By account panelUsage only splits when every configured account has its own transcripts directory. If two accounts share one config directory the data genuinely cannot be split, and the panel is hidden rather than showing a guess.
Build fails on a non-ASCII characterThe generated page is deliberately pure ASCII, since it declares no charset and must render correctly however it's opened. The error names the character and line — use an HTML entity or a \uXXXX escape in the template.

What these numbers are — and aren't

  • Claude Code CLI only. claude.ai, Desktop and Cowork share the same subscription but write nothing locally — every figure is a lower bound.
  • Not a bill. On Pro nothing here is charged; tokens are the currency.
  • Deduplicated. 52% of raw records are streaming partials or resume-copies; counting them naively doubles every total.
  • Cache reuse is the whole story. ~98% of tokens are re-read context billed at a fraction — why heavy use fits a flat plan.
  • Local-model noise removed. Ollama experiments were excluded by model name, not directory.
